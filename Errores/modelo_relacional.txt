1. RAZA
- id_raza (PK)
- nombre_raza
- origen
- caracteristicas
- aptitud
- peso_adulto_promedio_kg
- produccion_leche_dia_promedio
- estado
- fecha_creacion

2. ANIMAL
- id_animal (PK)
- codigo_identificacion
- nombre
- fecha_nacimiento
- sexo
- id_raza (FK a RAZA)
- color_pelaje
- peso_nacimiento_kg
- estado
- motivo_estado
- fecha_cambio_estado
- observaciones
- foto_url
- fecha_registro
- usuario_registro

Relacion:
- Una RAZA puede tener muchos ANIMAL.
- Cada ANIMAL pertenece a una sola RAZA.

3. GENEALOGIA
- id_genealogia (PK)

- id_padre (FK a ANIMAL)
- id_madre (FK a ANIMAL)

- coeficiente_consanguinidad
- observaciones
- fecha_registro

Relacion:
- Cada ANIMAL tiene un registro genealógico único.
- Padre y madre apuntan a ANIMAL como relaciones autorreferenciales.

Observaciones importantes
- El modelo cubre el núcleo funcional del sistema: raza, animales, genealogía, pesaje, producción, reproducción, salud y usuarios.
- No vi una tabla creada para NOTIFICACION; aparece como pendiente en la documentación.
- Hay una diferencia entre el SQL y la entidad Doctrine de genealogía: el SQL usa id_animal como cría principal, pero la entidad PHP usa id_cria.
- Para crear tablas, conviene seguir el script SQL como base principal y luego alinear el backend si hace falta.

Resumen corto de cardinalidades
- RAZA 1 --- N ANIMAL
- ANIMAL 1 --- N PESAJE
- ANIMAL 1 --- N PRODUCCION_LECHE
- ANIMAL 1 --- N SALUD
- ANIMAL 1 --- N REPRODUCCION como hembra
- ANIMAL 1 --- N REPRODUCCION como macho
- ANIMAL 1 --- 1 GENEALOGIA
- USUARIO 1 --- 1 USUARIO_PERFIL
- AUDITORIA queda independiente
